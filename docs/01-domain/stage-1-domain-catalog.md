# Royal City — Stage 1 Domain Catalog

## Purpose

This catalog is the current canonical inventory of domain concepts.

## Foundational participation layers

| Concept | Status | Meaning |
|---|---|---|
| Person | Established | Human participant with Royal City identity and account |
| Community | Established | Participating residential property or real-estate environment connected through community onboarding credentials |
| Royal City | Established | Network Operating System coordinating the ecosystem and providing Royal City-owned services |
| Community onboarding credentials | Established | Credentials used by a community to connect its management environment to Royal City |

## Established core

| Concept | Status | Meaning |
|---|---|---|
| Identity | Established | Unified participation representation for a person |
| Relationship | Established | Meaningful connection providing domain context |
| Authority | Established | Basis for exercising a power, responsibility, or control |
| Authorization | Established | Decision permitting or denying an action |
| Action | Established | Meaningful operation performed by a participant |
| Place | Established | Recognized physical/spatial domain |
| Resource | Established | Something that can be acted upon, controlled, accessed, allocated, or used |
| Service | Established | Capability made available to participants |
| Transaction | Established | Economic exchange/commitment where transactional semantics apply |
| State | Established | Current domain condition |
| Record | Established | Required persistent representation of a significant domain occurrence |

## Canonical participation patterns

Community:

`Community → Onboarding Credentials → Royal City Network Operating System → Community Management/Services/People/Places/Utilities/Economy`

Person through community:

`Person → Royal City Identity/Account → Community Relationship → Authorization → Community Participation`

Person directly through Royal City:

`Person → Royal City Identity/Account → Royal City-owned Service → Authorization → Action`

## Canonical distinction

`Participant → Identity or Participation Credentials → Relationship / Authority → Authorization → Action → Target → Result → State / Record`
