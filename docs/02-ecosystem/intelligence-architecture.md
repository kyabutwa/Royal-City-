# Royal City — Intelligence Architecture

## Principle

Intelligence assists the ecosystem; it does not become the authority system.

## Canonical intelligence path

`Purpose → Authorized Inputs → Context → Retrieval/Features → Model/Rules/Analytics → Output → Validation → Uncertainty → Attribution → Intelligence Record → Proposal/Decision Support`

For consequential operations:

`Request → Authentication → Context → Authorization → Intelligence → Proposal → Authorization → Command → Execution → Outcome`

## Mandatory boundaries

- model output ≠ authority;
- prompt ≠ policy;
- context ≠ permission;
- retrieval ≠ authorization;
- vector similarity ≠ truth;
- confidence ≠ authorization;
- recommendation ≠ action;
- tool availability ≠ tool authorization;
- agent ≠ administrator;
- automation ≠ authority.

## Data-purpose authorization

Royal City may use personal data for resource forecasting only when the person has explicitly authorized that use.

A technically accessible dataset is not automatically authorized input for a new purpose.

## Intelligence truth

Outputs must preserve uncertainty and provenance.

Intelligence may produce:

- observation;
- finding;
- prediction;
- forecast;
- recommendation;
- proposal;
- explanation.

These outputs do not become canonical domain state without the applicable governed process.

## Agents and automation

An automated actor should follow:

`Agent Identity → Task Scope → Tool Eligibility → Tool Authorization → Proposed Call → Command → Execution → Result → Event/Evidence`

Consequential actions require the same authorization and execution controls as human-initiated actions.

## Human review

High-risk or materially uncertain intelligence may require human review before authorization or execution, according to the applicable domain policy.
